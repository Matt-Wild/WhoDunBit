## Document scope

The GDD defines gameplay behaviour. The TDD defines technical requirements and proposed implementation approaches. Changes affecting both gameplay and system behaviour should be reflected in both documents. Implementation status is tracked separately.

## Design status

- **Proposed:** A candidate feature, content concept or architectural approach under evaluation.
- **Provisional:** An initial numerical value or configuration subject to validation and balancing.
- **TBD / open decision:** A rule or implementation choice requiring further design.

Unqualified gameplay rules represent the current design baseline. Goals and longer-term ambitions are described as such. Examples illustrate system behaviour without defining default configurations. Each document maintains a revision history.
